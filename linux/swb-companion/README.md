# EmberTCAD 0.1.0

EmberTCAD 是运行在 RHEL 兼容 Linux 桌面上的开源 Sentaurus TCAD AI 助手。它不依赖网页，也不随 Sentaurus Workbench 自动启动；当 SWB 已打开时，它会持续读取真实工程、参数、节点和结果，并通过受约束的本机桥接进行联动。

完整环境、架构、验收结果与后续路线见仓库根目录的 HANDOFF_CENTOS7_ASSISTANT.md。

## 安装与启动

    bash ./install.sh --check
    bash ./install.sh
    EmberTCAD

小写命令 `embertcad` 同样可用；`spark-ai` 与 `aitcad-native` 作为升级兼容别名保留。`swb_class` 只启动 SWB，EmberTCAD 由用户单独启动。安装程序会移除旧的 `aitcad-swb` / `nova-tcad` 启动入口和桌面项。

## 产品主流程

1. 每次新启动都停在 Project 选择引导页，不自动把默认工程当作用户选择。
2. 用户选择工程后，EmberTCAD 先在本机清点文件、Tool 链、参数、节点和已有结果，再把识别出的用户源文件交给已配置模型逐文件深度阅读。
3. 固定六阶段流程只展示当前一屏：`选择工程 → AI 理解 → 描述目标 → 审查方案 → 执行验证 → 完成`。每个阅读动作拥有独立状态、耗时和真实/动态进度。
4. 用户描述目标后，AI 检查工程上下文和必要证据，生成一份推荐方案与动态参数表；用户确认前不修改工程、不运行节点。
5. 确认后任务始终留在工作台执行；Tool 改写会复用证据、差异、SHA 校验、可恢复写入和真实节点验证组件。最终报告和恢复入口统一位于任务历史。
6. “AI 深度分析”显示可审计分析清单、结构化发现与推理摘要；工程连接确认后立即完成，不用动态进度伪装工作量。
7. 任务历史按工程归并为一工程一行；任务详情和报告在历史栏目内部展开，只有用户明确点击“继续此任务”才返回业务流程。
8. “设置”明确区分服务地址、模型 ID、接口协议和推理强度：API Key 只鉴权，模型 ID 才决定实际模型。OpenAI 官方默认使用 `gpt-6.1-sol` 与 Responses API；DeepSeek 和常见兼容服务继续使用 Chat Completions，不会因升级 OpenAI 适配而改变现有调用。设置页仍可测试 API；同时自动扫描本机 Sentaurus 安装，用户选择的版本会驱动后续手册、校验、运行和新开的 SWB。

已到达的工作台 1–6 步和从零创建 1–5 步都可以点击回看。回看只改变当前显示页面，不会重置任务、重启模型请求或中断后台执行；未来步骤在真实流程到达前仍保持锁定。方案表单只向用户询问必须决定的物理条件，工程源文件、失败节点、错误日志、安装版本和路径由 EmberTCAD 自动读取。

## 独立窗口

- 单一 GTK3 顶层窗口，不再提供或维护 SWB 侧栏模式。
- 默认 1400×900，不强制最大化、不置顶、不自动移动，用户可以自由放置和缩放。
- 左侧导航是固定宽度的独立列，始终贴住窗口左侧；右侧页面独占剩余空间，欢迎内容在主区内水平、垂直居中。
- 右侧“AI 执行记录”小窗已经从布局和代码中删除；聊天、工程理解、计划与确认都在任务工作台主页面完成。
- 所有产品页面禁止整体横向滚动；长报告、长聊天和输入内容在自己的视口内换行，不会再推动顶层窗口变宽。
- 右侧纵向滚动条加宽并常显；内层报告或聊天滚到底后，继续滚轮会自然推动外层页面。
- 选择工程后，工作台只显示当前阅读阶段和可折叠记录；AI 完成全部五个阅读子步骤后才切换到“阅读结果＋任务输入”。
- 方案审查的容器是通用组件，但内容由所选工程的真实源文件、接手报告、证据、动态参数和自适应卡片生成，并非针对某个演示工程写死。
- 工程读取、AI 对话、方案生成、历史、创建工程和节点动作的异步错误统一经过 Unicode 安全转换；中文错误会回到主页面，不会再让 Python 2 工作线程静默崩溃。
- 实机布局回归逐屏验证六阶段在 1000×700、1180×760 和 1420×860 下无页面横向滚动和尺寸漂移。

## 执行、停止与恢复

- P-well→Vth 和普通 Agent 不再有固定 8 次/12 轮上限；只在目标达成、用户停止、不可恢复错误或物理范围内没有新候选点时结束。
- 保留“相同工具、相同参数、工程无变化”的死循环熔断，并明确标记为暂停原因，而不是迭代上限。
- 每次真实执行都有唯一 `runId`。点击停止后任务先进入 `stopping`，AI Helper 和当前 gsub 进程组先收 SIGTERM，2 秒内不退出则 SIGKILL。
- 未完成产物不进入报告或下一轮判断；此前有效结果保留，最终状态持久化为 `cancelled`，晚到完成事件不能覆盖取消结果。
- 可保存、规划和切换多个任务，但同时只允许一个真实执行任务。

## 从自然语言创建真实工程

“从零创建工程”只要求描述研究需求，也可选择论文、报告或器件说明书 PDF 作为建模依据：PDF 在本机按页提取，只把相关页摘要发送给模型，报告保留页码和 SHA-256；纯扫描件在没有 OCR 时会明确停止。AI 先集中澄清必要物理条件，再检索当前版本 Manual/Tutorial，提出 Tool 链、假设、SWB 参数和完整源文件供逐文件审查。工程名可在批准前调整，用户也可通过目录选择器指定当前 STDB 工作区内任意现有上级目录；同名目标会自动建议新的兄弟名称，最终路径会重新预检并绑定审批指纹。用户确认后，Connector 用当前安装的 SWB 接口建树；只有真实节点为 done 且产生了新产物才称为运行验证成功。没有配置模型或缺失依据时停止在规划阶段，不复制固定 NMOS 模板冒充生成。草稿、取消和已创建工程关联到任务历史。

如果同一 Project 已在 SWB 中打开，EmberTCAD 只刷新该窗口；如果用户当前打开的是其他 Project，则为新工程启动独立 SWB 窗口，不替换或关闭用户正在使用的窗口。

用户已明确允许将需求、手册摘要和必要源文件发送给其配置的模型服务。正式版发布前已真实重放用户失败的三 Tool PN 工程：修复跨 Tool 参数步号漂移，并将无效 CurrentPlot、NetActive 和错误参数文件命名前移到本地预检；SDE/SDevice 节点依次 `done`，产生网格、Current PLT 和日志。基线验收逐个运行计算节点，不再误启动会阻塞后台的 SVisual。模型输出仍必须通过本机预检、人工批准、指纹复核和真实 `.sta`/产物验收，不会因为模型“说完成”就算成功。

复杂工程可选三种验收等级：快速预检不运行仿真；标准验收只运行最短代表性依赖路径；完整验收运行全部叶节点。默认使用标准验收，避免为了交付而强迫用户等待耗时的全工程扫描。任何失败都会展示实际 Tool、节点、错误文件和行号，并把修复目标带回任务工作台。

安装程序支持 `--check`、自定义工程根目录、Sentaurus 根目录和辅助 Python。CentOS 7 已做真实端到端验证；Rocky/Alma 8+ 与 CentOS Stream 采用同一 RHEL 兼容探测路径，但仍应在具体 Sentaurus 主机上先运行 `--check`。从 GitHub 的一行安装命令见仓库根 README。

## 通用模型研究与 Tool 改写

工作台里的 Tool 修改目标面向 SDevice、SProcess、SDE 和 Inspect 的任意物理模型：

1. 检索当前 Sentaurus 版本的本机 PDF Manual 和 Applications Library Tutorial；可选读取论文题录/摘要。
2. 识别真实用户源文件、SWB Tool step 和源 SHA-256。
3. 模型结合目标、源文件和证据生成物理假设、动态参数、验证计划和完整文件差异。
4. 本机检查结构、危险命令/路径、异常大差异和源文件 SHA。
5. 左侧不再出现独立的 Tool 修改入口；多文件差异并入工作台推荐方案，一次确认后在同一工作台完成备份、写入和节点验证。
6. 以 .sta、日志和结果文件判断完成，生成带 SHA、备份和产物的报告。

从零创建逐屏显示“描述需求 → 依据与澄清 → 审查工程蓝图及文件 → 创建并验证 → 交付”。手册中心与工程级历史档案仍独立保留。

TID/Trap 只是可选 recipe，不拥有专用 UI。不同物理模型的参数、证据、扫描和验证计划由任务动态生成。

## 数据与安全

工程阅读会把所选工程中识别出的用户源文件发送给当前配置的模型；不发送密钥或工作区外文件。模型调用本身不修改工程、不运行节点。API Key 保存在 ~/.config/aitcad/model.json，权限应为 0600。

全部任务明细持久化在 `~/.local/share/aitcad/research/tasks.sqlite3`，Markdown 报告保存在 `~/.local/share/aitcad/research/reports/`。升级应用代码不会覆盖这些用户数据。

## 模型设置

- **API 服务地址**决定请求发送到哪家服务，例如 `https://api.deepseek.com` 或 `https://api.openai.com/v1`。
- **模型 ID**决定实际调用的模型；同一个 API Key 可以有权访问多个模型，但不会自动在 Sol、Astra、Luna 或其他模型之间选择。
- **接口协议**决定请求格式。OpenAI 的现代推理模型在 EmberTCAD 中使用 Responses API，以支持工作台工具调用；DeepSeek 与通用兼容服务默认使用 Chat Completions；Claude 使用 Anthropic Messages。
- **推理强度**只调整同一个模型的推理投入，不改变模型身份，也不表示 EmberTCAD 会显示供应商的私有思维链。`自动`表示保留模型默认值，`标准`表示不附加额外推理参数。
- OpenAI、DeepSeek 等预设模型只是方便选择的建议值。服务商更新型号后，可以直接输入账户实际可用的精确模型 ID。
